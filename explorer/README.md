# Reqvire Explorer (SPA shell)

Native static single-page Explorer for the Reqvire Project Store. Built with
Vite + TypeScript + React and an in-tree design system; no Tailwind, no Radix
Themes, no CDN dependencies.

The served `index.html` **is** this bundle: `core/build.rs` embeds the built
`dist/`, and `reqvire serve` supplies the generated Project Store as
`assets/project-store.js`. Explorer views are SPA routes.

Every route renders natively from the store (model, graph, traces,
ontologies, coverage, resources, files, search, and the element-detail modal).
The Model route offers List/Grid browsing plus a Sigma/Graphology graph mode.
The Ontologies route uses a Sigma ontology renderer when ontology graph data is
present.

## Design system

The Explorer ships its own self-contained design system under `design-system/`.

### Authoring
All component source lives in `design-system/components/` as TSX files. Every
component is re-exported by `design-system/index.ts` (the `@ds` path alias).
Application code must import from `@ds` only — never from component paths
directly. An oxlint config generated by `npm run generate:adherence` enforces
this contract.

Namespace ownership is strict. `ds-*` classes and `--ds-*` component variables
belong to reusable design-system primitives. `ux-*` classes and `--ux-*`
variables belong to reusable UX/product patterns. Application code must not
emit either namespace directly.

Application styles must not target design-system internals such as
`.ds-treeitem`, `.ds-tabs`, `.ds-search__input`, or `.ds-togglerow__label`.
Customize design-system components through documented props or documented
`--ds-*` component variables exposed by the owning UX/product pattern.

### Tokens
CSS custom properties are organized under `design-system/tokens/`:
`colors.css`, `typography.css`, `spacing.css`, `elevation.css`, `fonts.css`,
`base.css`. All values in application CSS (`src/**/*.css`) must reference tokens
via `var(--token)`. Raw `px`, colors, font stacks, numeric weights, durations,
and easings are only permitted inside custom-property declarations and at-rule
conditions.

A **style token guard** at `scripts/lint-style-tokens.mjs` enforces this
contract on every build. There is no baseline — any violation fails the run.

Design-system components follow the same visual-value rule. Component APIs
should expose semantic variants, token names, roles, or documented `--ds-*`
variables; they must not expose arbitrary CSS color-string props.

### Fonts
Geist and Geist Mono are vendored in `design-system/assets/fonts/` as variable
`.woff2` files and referenced by relative URL from `tokens/fonts.css`. No CDN
or Google Fonts.

### Palette API
`design-system/palette.ts` is the canonical programmatic color API:
`ELEMENT_ROLE_TOKENS`, `ELEMENT_TYPES`, `cssVar()`, `getMermaidClassDefs()`,
`roleColorToken()`, `roleColorValue()`, `elementRole()`. Import from `@ds`; do
not reach into `palette.ts` directly.

### Generated artifacts
Generated bundles, generated CSS, favicon/app-icon PNG/ICO outputs, and
`dist-*` outputs are build/runtime artifacts only. They are not tracked as
source in this repository, with no release-artifact exception. Source of truth
is TS/TSX, CSS tokens, config, docs, and `design-system/assets/logo-mark.svg`
for brand-derived browser icons.

`index.html` owns the tiny document mount bootstrap: root/body height plus the
Explorer body overflow policy. Product UI styling belongs with the owning
Explorer component or the owning design-system component. Body typography,
colors, reset rules, selection styling, and scrollbars belong to
`design-system/tokens/base.css`.

## Build & embed flow

`npm run build` is lint-gated:

```
npm run lint && npm run generate:icons && tsc --noEmit && npm run build:ds-bundle && vite build
```

`npm run lint` runs three checks in sequence:
1. **`lint:artifacts`** — rejects tracked/generated bundles, generated CSS,
   generated browser icons, generated adherence config, and `dist-*` outputs.
2. **`lint:adherence`** — regenerates the ignored
   `.vite/_adherence.oxlintrc.json` then runs oxlint with `--deny-warnings` to
   enforce the `@ds` component import contract.
3. **`lint:style`** — stylelint (selector/property correctness), the token
   guard (`scripts/lint-style-tokens.mjs`), and the CSS/import architecture
   guard (`scripts/lint-css-architecture.mjs`).

`vite build` emits deterministic, unhashed assets (`assets/explorer.js` +
`assets/explorer.css`). The asset contract validates `design-system/assets/`,
generated browser assets, and optional `public/assets/` raw URL inputs, then
assembles the build output under `dist/assets/`; matching asset filenames fail
the build. `core/build.rs` copies `dist/` into `OUT_DIR` so `cargo build`
embeds it. **Build the Explorer before `cargo build`** — the compiled bundle is
a required build input.

## Interface expected from `reqvire serve`

The SPA reads an immutable browser-local **Project Store** seed produced from
`core/src/html/store.rs`. The frontend resolves the seed in this order (see
`src/store/loadStore.ts`):

1. `window.reqvireProjectStore` — a global set by `assets/project-store.js`
   loaded by the SPA before React mounts.
2. The dev fixture, only during `npm run dev` (no seed → `MissingStoreNotice`
   in production builds).

The runtime seed has this shape:

```js
window.reqvireProjectStore = { /* ExplorerProjectStore JSON */ };
```

### Runtime contract

- **Serve the seed at the runtime URL.** The SPA loader requests
  `assets/project-store.js` before mounting React. That runtime script must
  assign `window.reqvireProjectStore`; it is generated by `reqvire serve`, not
  checked into Explorer source.
- **Mount point.** `index.html` must contain `<div id="root"></div>` and
  include `assets/explorer.js` and `assets/explorer.css`.
- **Schema version.** `schema_version` must equal `EXPECTED_SCHEMA_VERSION` in
  `src/store/types.ts`, kept in sync with `SCHEMA_VERSION` in `store.rs`. A
  mismatch renders a visible non-fatal banner; a missing or malformed seed fails
  closed.
- **Schema shape.** Top-level keys mirrored in `src/store/types.ts`:
  `schema_version`, `project`, `folders`, `files`, `resources`, `elements`,
  `relations`, `attachments`, `concept_refs`, `submodels`, `traces`, `coverage`,
  `ontology`, `knowledge_graph`, `search`, `summaries`, `routes`.

`src/store/types.ts` is the authoritative TypeScript mirror of the Rust structs.

### Scope boundary

Explorer owns the browser shell and design system. Rust owns normalized Project
Store data and the embedded Vite bundle served by `reqvire serve`.
