Reqvire requirements & traceability management tool

Usage: reqvire [OPTIONS] <COMMAND> [COMMAND OPTIONS]

Commands:
  export            Export model to browsable HTML documentation with complete traceability
  serve             Serve model as browsable HTML documentation via HTTP server
  mcp               Start Reqvire MCP server
  format            Format and normalize requirements files. By default, shows preview without applying changes
  validate          Validate model
  search            Search and filter model elements with comprehensive filtering options
  change-impact     Analyze change impact and provide report
  traces            Generate verification traces showing upward paths from verifications to capability-rooted requirements
  coverage          Generate verification and implementation coverage report
  model             Generate model-centric structure with nested relations
  lint              Analyze model quality and detect issues in requirements relations
  add               Add new element to model from Markdown definition
  rm                Remove element from model
  mv                Move element to different location
  rename            Rename element
  merge             Merge multiple elements into target element
  mv-file           Move entire specification file with all its elements
  link              Add relation or attachment between elements
  unlink            Remove relation or attachment between elements (auto-detects type)
  relink            Replace an existing relation target with a new target in one operation
  mv-asset          Move/rename asset file and update all references (Attachments and Relations)
  rm-asset          Remove asset file and remove all references (Attachments and Relations)
  containment       Generate containment view showing folder/file/element hierarchy
  resources         Generate resources report showing files referenced by the model
  ontologies        Collect ontology elements and semantic-contract SHACL shapes
  submodels         Analyze independent requirement submodels and cross-submodel couplings
  collect           Collect content from capability or requirement context
  help               Print this message or the help of the given subcommand(s)

Options:
  --workspace <DIR>         Workspace directory to operate on
  -h, --help               Print help
  -V, --version            Print version

EXPORT OPTIONS:
      --output <OUTPUT>         Output directory for HTML files (defaults to temporary directory if not specified)

SERVE OPTIONS:
      --host <HOST>             Bind address
      --port <PORT>             Server port

MCP OPTIONS:
      --host <HOST>             HTTP bind address
      --port <PORT>             HTTP server port
      --enable-mutations        Advertise and allow mutation tools
      --with-size-estimates     Include element size estimates in model evidence tools

FORMAT OPTIONS:
      --fix                     Apply formatting changes to files
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)
      --with-full-relations     Include all relations (user-created and auto-generated inverse relations)

VALIDATE OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

SEARCH OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)
      --short                   Output abbreviated format (one-line per element in text, omit fields in JSON)
      --filter-file <GLOB>      Only include files whose path matches this glob pattern e.g. `src/**/*Reqs.md`
      --filter-name <REGEX>     Only include elements whose name matches this regular expression
      --filter-type <TYPE[,TYPE...]> Only include elements of the given type(s). Supports comma-separated list. Valid: capability, requirement, ontology, test-verification, formal-proof-verification, analysis-verification, inspection-verification, demonstration-verification, source, semantic-contract, constraint, behavior, specification, state, input-output. Custom: other-TYPENAME
      --filter-status <STATUS[,STATUS...]> Only include requirement-family elements with matching effective status values
      --filter-priority <PRIORITY[,PRIORITY...]> Only include requirement-family elements with matching effective priority values
      --filter-risk <RISK[,RISK...]> Only include requirement-family elements with matching effective risk values
      --filter-owner <REGEX>    Only include requirement-family elements whose effective owner matches this regular expression
      --filter-content <REGEX>  Only include elements whose content matches this regular expression
      --filter-page-content <REGEX> Only include elements whose parent file page content matches this regular expression
      --have-relations <LIST>   Only include elements that have ALL specified relations (comma-separated, e.g., "verifiedBy,satisfiedBy")
      --not-have-relations <LIST> Only include elements that do NOT have ALL specified relations (comma-separated, e.g., "verifiedBy")
      --has-attachments         Only include elements that have attachments
      --filter-attachment <GLOB> Only include elements with attachments matching this glob pattern (e.g., "*.pdf", "docs/**/*")

CHANGE IMPACT OPTIONS:
      --git-commit <GIT_COMMIT> Git commit hash to use when comparing models
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

TRACES OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)
      --from-folder <PATH>      Relative path to folder where output will be saved (for generating relative links in Mermaid diagrams)
      --links-with-blobs        Use GitHub blob URLs in diagram links instead of relative paths
      --filter-id <ID>          Only include verification with this specific identifier
      --filter-name <REGEX>     Only include verifications whose name matches this regular expression
      --filter-type <TYPE>      Only include verifications of the given type. Valid: test-verification, analysis-verification, inspection-verification, demonstration-verification

COVERAGE OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

MODEL OPTIONS:
      --from <NAME>             Start from specific element by name
      --reverse                 Traverse from leaves to roots (follow backward relations)
      --filter-type <TYPE>      Filter starting elements by type (comma-separated). Valid: capability, requirement, ontology, test-verification, formal-proof-verification, analysis-verification, inspection-verification, demonstration-verification, source, semantic-contract, constraint, behavior, specification, state, input-output. Custom: other-TYPENAME
      --json                    Output results in JSON format (nested structure)
      --mmd                     Output pure Mermaid flowchart text
      --with-size-estimates     Include element size estimates in JSON output
      --output <FILE>           Save output to file (requires --json or --mmd)

LINT OPTIONS:
      --fixable                 Show only auto-fixable issues
      --auditable               Show only issues requiring manual review
      --fix                     Apply automatic fixes for auto-fixable issues
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

ADD OPTIONS:
       <FILE>                   Target file path (relative to git repository root)
      --content <MARKDOWN>      Element markdown content (alternative to stdin)
      --override                Replace existing element with same name
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

RM OPTIONS:
       <ELEMENT_NAME>           Element name
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

MV OPTIONS:
       <ELEMENT_NAME>           Element name
       <FILE>                   Target file path (relative to git repository root)
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

RENAME OPTIONS:
       <ELEMENT_NAME>           Current element name
       <NEW_NAME>               New element name
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

MERGE OPTIONS:
       <TARGET>                 Target element name (receives merged content)
       <SOURCES>                One or more source element names to merge into target
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

MV FILE OPTIONS:
       <SOURCE_FILE>            Source file path (relative to current working directory)
       <TARGET_FILE>            Target file path (relative to current working directory)
      --squash                  Move all elements to target file's first section (if target exists)
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

LINK OPTIONS:
       <SOURCE>                 Source element name
       <RELATION_TYPE>          Relation type OR 'attaching'. Relations: derivedFrom, derive, satisfiedBy, satisfy, verifiedBy, verify, trace. Use 'attaching' to attach capability ontology context or compatible requirement-owned refinement contracts
       <TARGET>                 Target: element name, internal path, or external URL (for relations); ontology for capability attachments or compatible refinement element identifier for requirement attachments
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

UNLINK OPTIONS:
       <SOURCE>                 Source element name
       <TARGET>                 Target element name OR file path
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

RELINK OPTIONS:
       <SOURCE>                 Source element name
       <RELATION_TYPE>          Relation type to preserve
       <FROM_TARGET>            Existing target to replace
       <TO_TARGET>              New target
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

MV ASSET OPTIONS:
       <OLD_PATH>               Current file path
       <NEW_PATH>               New file path
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

RM ASSET OPTIONS:
       <FILE_PATH>              Path to file to remove
      --dry-run                 Preview changes without applying
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

CONTAINMENT OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)
      --short                   Show only root elements (without hierarchical parents in same file)

RESOURCES OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

ONTOLOGIES OPTIONS:
      --jsonld                  Output JSON-LD format instead of RDF/Turtle (.ttl)
      --full                    Include Reqvire model context triples in the semantic export
      --output <FILE>           Save output to file

SUBMODELS OPTIONS:
      --from <NAME>             Scope report to a specific requirement subtree by name
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

COLLECT OPTIONS:
       <ELEMENT_NAME>           Name of the capability or requirement element to collect from
      --direction <DIRECTION>   Traversal direction: UPSTREAM (ancestors) or DOWNSTREAM (descendants)
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)
