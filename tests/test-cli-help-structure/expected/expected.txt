Reqvire requirements & traceability management tool

Usage: reqvire [OPTIONS] <COMMAND> [COMMAND OPTIONS]

Commands:
  serve             Serve the embedded Explorer UI via HTTP server
  export            Export the Explorer SPA as a static site to a directory
  mcp               Start Reqvire MCP server
  migrate           Preview or apply source migrations for known model-breaking changes
  validate          Validate model
  search            Search and filter model elements with comprehensive filtering options
  change-impact     Analyze change impact and provide report
  traces            Generate verification traces showing upward paths from verifications to capability-rooted requirements
  coverage          Generate verification and implementation coverage report
  model             Generate model-centric structure with nested relations
  lint              Analyze model quality and detect issues in requirements relations
  containment       Generate containment view showing folder/file/element hierarchy
  resources         Generate resources report showing files referenced by the model
  semantic          Export semantic RDF layers
    semantic query  Manage authored SPARQL query artifacts
    semantic export Export selected semantic RDF layers
  concepts          Work with standalone Reqvire concept schemes and thesaurus concepts
    concepts export Export generated SKOS concept scheme/thesaurus triples
    concepts validate Validate standalone concept schemes, concept references, and mappings
  ontologies        Compatibility alias for combined semantic export
  submodels         Analyze independent capability-rooted submodels and cross-submodel couplings
  collect           Collect content from capability, requirement, ontology, semantic-query, concept-scheme, or concept context
  help               Print this message or the help of the given subcommand(s)

Options:
  --workspace <DIR>         Workspace directory to operate on
  --manifest <FILE>         Override Repo manifest location (default: .repo/manifest.xml)
  -h, --help               Print help
  -V, --version            Print version

SERVE OPTIONS:
      --host <HOST>             Bind address
      --port <PORT>             Server port
      --enable-mcp              Also serve the Reqvire MCP Streamable HTTP endpoint at /mcp
      --enable-mutations        Advertise and allow mutation tools on the embedded MCP endpoint
      --enable-commits          Commit successful mutations automatically (default: false; requires --enable-mutations)
      --enable-github           Enable same-repository GitHub publication (requires --enable-mutations)
      --github-remote <NAME>    Configured publication remote (default: origin; requires --enable-github)
      --allow-origin <ORIGIN>   Additional MCP browser origin (repeatable; loopback remains allowed)
      --allow-host <HOST[:PORT]> Additional MCP endpoint host or host:port (repeatable; requires --enable-mcp)

EXPORT OPTIONS:
      --output <OUTPUT>         Output directory

MCP OPTIONS:
      --transport <TRANSPORT>   MCP transport (default: http; values: http, stdio)
      --host <HOST>             HTTP bind address (HTTP-only)
      --port <PORT>             HTTP server port (HTTP-only)
      --enable-mutations        Advertise and allow mutation tools
      --enable-commits          Commit successful mutations automatically (default: false; requires --enable-mutations)
      --enable-github           Enable same-repository GitHub publication (requires --enable-mutations)
      --github-remote <NAME>    Configured publication remote (default: origin; requires --enable-github)
      --with-size-estimates     Include element size estimates in model evidence tools
      --allow-origin <ORIGIN>   Additional browser origin (HTTP-only; repeatable; loopback remains allowed)
      --allow-host <HOST[:PORT]> Additional endpoint host or host:port (HTTP-only; repeatable)

MIGRATE OPTIONS:
      --fix                     Apply migration changes to files
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

VALIDATE OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

SEARCH OPTIONS:
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)
      --short                   Output abbreviated format (one-line per element in text, omit fields in JSON)
      --filter-file <GLOB>      Only include files whose path matches this glob pattern e.g. `src/**/*Reqs.md`
      --filter-name <REGEX>     Only include elements whose name matches this regular expression
      --filter-type <TYPE[,TYPE...]> Only include elements of the given type(s). Supports comma-separated list. Valid: capability, requirement, ontology, concept-scheme, concept, test-verification, formal-proof-verification, analysis-verification, inspection-verification, demonstration-verification, verification-objective, source, semantic-query, semantic-contract, constraint, behavior, specification, state, input-output. Custom: other-TYPENAME
      --filter-status <STATUS[,STATUS...]> Only include requirement-family elements with matching effective status values
      --filter-priority <PRIORITY[,PRIORITY...]> Only include requirement-family elements with matching effective priority values
      --filter-risk <RISK[,RISK...]> Only include requirement-family elements with matching effective risk values
      --filter-owner <REGEX>    Only include requirement-family elements whose effective owner matches this regular expression
      --filter-content <REGEX>  Only include elements whose content matches this regular expression
      --filter-page-content <REGEX> Only include elements whose parent file page content matches this regular expression
      --have-relations <LIST>   Only include elements that have ALL specified relations (comma-separated, e.g., "verifiedBy,satisfiedBy")
      --not-have-relations <LIST> Only include elements that do NOT have ALL specified relations (comma-separated, e.g., "verifiedBy")
      --has-contract-bindings   Only include elements that have contract_bindings
      --filter-contract-bindings <GLOB> Only include elements with contract_bindings matching this glob pattern (e.g., "*.pdf", "docs/**/*")
      --has-contract-references Only include elements that have Contract References
      --filter-contract-references <GLOB> Only include elements with Contract Reference targets matching this glob (e.g., "*#error-response-specification")

CHANGE IMPACT OPTIONS:
      --git-commit <GIT_COMMIT> Base Git commit (includes the historical manifest in Repo mode) [default: HEAD]
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

TRACES OPTIONS:
      --output <FILE>           Save JSON output to file
      --filter-id <ID>          Only include verification with this specific identifier
      --filter-name <REGEX>     Only include verifications whose name matches this regular expression
      --filter-type <TYPE>      Only include verifications of the given type. Valid: test-verification, analysis-verification, inspection-verification, demonstration-verification

COVERAGE OPTIONS:
      --from <NAME>             Select a capability subtree by exact name or canonical identifier
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

MODEL OPTIONS:
      --from <NAME>             Start from specific element by exact name or canonical identifier
      --reverse                 Traverse from leaves to roots (follow backward relations)
      --filter-type <TYPE>      Filter starting elements by type (comma-separated). Valid: capability, requirement, ontology, concept-scheme, concept, test-verification, formal-proof-verification, analysis-verification, inspection-verification, demonstration-verification, verification-objective, source, semantic-query, semantic-contract, constraint, behavior, specification, state, input-output. Custom: other-TYPENAME
      --with-size-estimates     Include element size estimates in JSON output
      --output <FILE>           Save JSON output to file

LINT OPTIONS:
      --fixable                 Show only auto-fixable issues
      --auditable               Show only issues requiring manual review
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

CONTAINMENT OPTIONS:
      --output <FILE>           Save JSON output to file
      --short                   Show only root elements (without hierarchical parents in same file)

RESOURCES OPTIONS:
      --output <FILE>           Save JSON output to file

SEMANTIC EXPORT OPTIONS:
      --layer <LAYER>           Include layer: ontologies, shapes, concepts, queries, model, external-used, prefixes. Repeatable; omitted means all layers
      --jsonld                  Output JSON-LD format instead of RDF/Turtle (.ttl)
      --namespace-base <IRI>    Filter clean authored export to one ontology base or term namespace. Cannot be combined with model
      --output <FILE>           Save output to file

CONCEPTS EXPORT OPTIONS:
      --jsonld                  Output JSON-LD format instead of RDF/Turtle (.ttl)
      --include-mappings        Include structural reqvire:mapsToConcept bridge triples that point to generated native concepts
      --output <FILE>           Save output to file

CONCEPTS VALIDATE OPTIONS:
      --json                    Output validation result in JSON format
      --output <FILE>           Save JSON output to file

ONTOLOGIES OPTIONS:
      --jsonld                  Output JSON-LD format instead of RDF/Turtle (.ttl)
      --full                    Include Reqvire model context triples and ontology projection facts in the semantic export
      --include-external        Include used local external ontology subset triples
      --namespace-base <IRI>    Filter clean authored export to one ontology base or term namespace
      --output <FILE>           Save output to file

SUBMODELS OPTIONS:
      --from <NAME>             Scope report to a capability subtree or requirement subtree by exact name or canonical identifier
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)

COLLECT OPTIONS:
       <ELEMENT_NAME>           Exact name or canonical identifier of the capability, requirement, ontology, semantic-query, concept-scheme, or concept element to collect from
      --direction <DIRECTION>   Traversal direction: UPSTREAM (ancestors) or DOWNSTREAM (descendants)
      --json                    Output results in JSON format
      --output <FILE>           Save JSON output to file (requires --json)
